B · 行为引导模式第 06 章

给用户看的文字与子任务专用提示

一段正确内容发给不同接收者，可能需要不同形式。constants/prompts.ts:416-428 和 constants/prompts.ts:402-415 把外部用户与内部用户的沟通分开；摘要和笔记又另有输出结构。本章从这些文本看“简短”限定了什么，以及为什么一般工程要求不能直接套进压缩或记忆子任务。

简短回复先保留什么

外部 Output efficiency 要求先给答案或动作，省复述、过场和不必要解释。它列出仍应保留的信息：需要用户决定的事项、自然里程碑、会改变计划的错误或阻塞。最后明确豁免代码与工具调用。限制的是用户看到的说明文字，不是要求代码实现按同样的词数截断（B-20）。

原文依据：constants/prompts.ts:416-428。

内部 Communicating with the user 则要求首次工具前说明动作，在关键发现、改方向或长时间无更新后给进度。原文假定用户可能离开并失去线程，因此避免代号、缩写与残句；专家可更简短，新手可解释多些。这一分支把“读者能够重新接上”写成文字要求，与一律压字数不同（B-21）。

原文依据：constants/prompts.ts:402-415。

它还明确讨论表格用途：短可枚举事实或定量数据合适，不把长推理塞进单元格；一句话应能顺着读，不反复改口让读者回看。末尾同样把代码和工具调用豁免。于是，两个分支有不同的篇幅倾向，却共同要求回复服务当前用户，而不是记录模型处理日志。

Tone and style 指定代码引用格式 file_path:line_number、GitHub owner/repo 编号，以及默认不用 emoji。工具调用前不写冒号，理由直接在原句里：调用可能不显示在用户界面，冒号后面看不到东西。这里是作者对输出载体的具体假设，引用这个理由比另造“注意力”解释准确（B-22）。

原文依据：constants/prompts.ts:430-442。

数值限制不是所有任务的统一长度

内部用户动态段要求工具间文本不超过二十五词，最终回复不超过一百词，任务需要更多细节时例外。注释说相对定性 be concise 约减少 1.2% 输出 token，先在内部测质量。本章将数字归属为注释中的记录；规则本身能核验的是谁加入这段以及英文限制如何写（B-23）。

语言段要求解释、注释和沟通使用配置语言，技术名保留原样；风格段把名字和完整 prompt 放入数组（constants/prompts.ts:142-158）。这些要求同处动态装配，不意味着中文也按“英文词”有一个源码给出的统一分词算法。当前段只有词数措辞，无法从它推出输出长度的精确计数器。

token 目标另要求用户指定目标后继续工作到接近目标，称其为最低要求；段缓存的安排见第 2 章，实际继续判定见第 14 章。它约束工作轮次与预算，数值长度段约束说明文字，两者的对象不同。简单把 minimum 与百词要求放在一栏比较，会忽略代码、工具调用和后续轮次（constants/prompts.ts:538-551）。

接收者换成了另一个 agent

DEFAULT_AGENT_PROMPT 要求完成任务后简短报告成果和发现，说明调用者会转告用户。增强附注又要求绝对文件路径，代码片段只在具体文字决定结论时给出，禁止复述读过的代码。报告的接收者是调用者，报告内容应让它能接着决策，不能把原始搜索过程逐项倾倒（B-27）。

环境段还带当前目录、worktree 与 shell 信息，MCP 段只拼已连接服务器的 instructions；delta 开启时改变传递位置。这些装配细节已由第 1 章详述（constants/prompts.ts:651-710、constants/prompts.ts:579-604、utils/attachments.ts:1558-1585）。子任务文字中的“绝对路径”与环境所示 cwd 配对，是实际执行上下文的提醒，而不只是回复格式偏好。

工具结果可能被清除时，提示要求模型把后面还需要的信息写到自己的回复里。Function Result Clearing 则受特性、配置和模型支持条件控制，并告知保留最近 keepRecent 条；公共总结句提醒原工具结果可能消失（B-29）。

这段把用户可见文字同时用作后续上下文中的材料，但并没有允许把所有工具输出完整再抄一遍。要写下的是以后会用的重要信息；具体删除与恢复预算在第 15 章讨论。这里先看到输出形式与上下文寿命之间的接口：模型的回复不只传给人，也会留在未来的消息序列中。

摘要子任务先禁止调用工具

compact 的 NO_TOOLS_PREAMBLE 要求只输出文本，禁止所有工具，并说明唯一回合会因被拒绝的调用浪费。注释解释它继承父工具集以共享缓存，特定模型曾无视较弱尾部禁令，记录了回退比例。作者因此把强前导放最前；这是注释说的诊断与处理原因（B-32）。

摘要基础模板要求记录用户明确请求、技术点、文件、错误、全部非工具用户消息、待办、当前工作与下一步；下一步必须贴最近明确请求，并保留原话。它不是让模型借摘要回合继续改项目，工具禁令与任务目标共同收窄了这个回合的用途（services/compact/prompt.ts:12-26、services/compact/prompt.ts:28-44、services/compact/prompt.ts:61-143、services/compact/prompt.ts:269-303）。

续接消息又是另一份 prompt：它先说明前面的内容是历史摘要，可附完整转录路径，有保留消息时说明其逐字保留。自动继续要求接着旧任务，不复述、不问“现在做什么”，自主模式再补“不是首次唤醒”。这个否定针对当前事件，防止把摘要后的轮次误当初次 tick（B-33）。

所以，生成摘要与使用摘要不是同一次输出协议。前者必须遵守分析/摘要结构，后者必须恢复最新任务。若只查到 compact 的摘要模板，就把“继续别问问题”当生成器要求，会混淆调用阶段；恢复上下文时是否有完整转录和最近原文也改变了模型可用材料。

笔记更新限定内容来源与编辑位置

会话笔记 prompt 明确排除当前记笔记指令、系统提示、CLAUDE.md 和旧摘要。唯一任务是 Edit 笔记后停止；标题与斜体描述必须保留，只更新下面内容。没有实质新信息的节可以不写，Current State 则要更新。它还两次提醒不要把记笔记流程写进笔记本身（B-34）。

原文依据：services/SessionMemory/prompts.ts:43-81。

这一排除很具体：系统给模型的编辑规则不属于用户讨论过的事情，保存它们会把抽取流程和被抽取材料混合。标题、模板说明和真正笔记又有不同可编辑权限。模板固定不是要求每节都填一段“暂无信息”；原文允许留空，避免把结构完整误读成内容必须填满。

跨会话抽取的 opener 只允许最近 newMessageCount 条消息作为保存来源，禁止为确认模式继续 grep 源码、读代码或跑 git。推荐有限回合中先并行 Read，再并行 Write/Edit，因为编辑需要先读。这是抽取子任务的范围，不能把“禁止核验源码”拿去指导主 agent 修 bug（B-35）。

原文依据：services/extractMemories/prompts.ts:26-44。

团队记忆提示还把持久保存与当前进度分开：计划变更写计划，离散步骤写任务，未来会话需要的资料写记忆；用户要求忽略记忆时应视入口为空（memdir/teamMemPrompts.ts:68-94）。相同的“做笔记”动词在不同子任务里对应不同材料、目录和生命周期，最终要按 prompt 的来源限制与实际权限回调一起检查，具体回调见第 16 章。

本卷到此把字句接回了运行阶段：面向人的说明、面向调用者的报告、摘要输出、笔记编辑都指定了接收者和停点。下一卷从工具接口继续追踪，查看这些小流程到底存在哪个字段、模型什么时候能看到它们。第 7 章将先分清两个叫 description 的位置。
